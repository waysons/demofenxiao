# demofenxiao：市场动态排序与节点编辑模拟设计

日期：2026-10-17  
状态：已定稿  
范围：**仅本仓库 `demofenxiao` 静态模拟站**；不修改 `YUANHE_express` 生产代码。

## 背景与目标

`YUANHE_express` 的分销规则（七人拼团、成团滑落、县/市/省代理、左右位/扶持区）需要一个可操作的族谱分裂模拟网站，方便演练：

1. 设置县级 / 市级 / 省级代理  
2. 对节点设置是否购买 199、购买时间（用于市场排序）  
3. 七人成团必须真人直推 ≥ 2（防单链）  
4. 成团后自动滑落一张复投，帮助左链最底节点凑团  
5. 同级直推按「市场活跃」动态重排：有裂变的靠前，避免前两位无下级导致没有市场

本设计把上述能力落到 `outputs/demofenxiao`，规则对齐后端 `distRewardRules`（以当前引擎已实现部分为基线，补齐缺口）。

## 决策摘要

| 项 | 选择 |
|----|------|
| 实现范围 | 只改 demofenxiao（engine / UI / README / tests） |
| 结算策略 | 方案 2：席位动态重排；**新入团单**按当前席位发奖；日常不冲正已记流水 |
| 市场排序 | 规则 A：有裂变（名下 ≥1 已入团真人）优先；同档按本人 `joinedAt` 新→旧 |
| 节点编辑 | 树上/侧栏可改代理、购买时间；「仅标记」与「模拟购买入团」两种 |
| 团长定义 | 与后端一致：已入团真人直推 ≥ 3，**不要求**自身七人成团 |
| 成团门槛 | 满 7 **且** 真人直推 ≥ 2；单链满 7 不成团，补第 2 直推后补发并滑落 |

## §1 内存数据模型

不落库。每个用户节点至少包含：

| 字段 | 含义 |
|------|------|
| `agentLevel` | `""` \| `county` \| `city` \| `province` |
| `joined` | 是否已模拟购买入团 |
| `joinedAt` | 入团时间（可手改；市场同档排序键） |
| `marketMarked` | 仅标记已购（不结算） |
| `marketMarkedAt` | 仅标记时间（展示用，不参与结算席位） |
| 既有字段 | `children`、`reentry`、`groupAwarded`、钱包与账本等保持 |

约束：

- **结算席位**只认 `joined === true` 的真人；排序键用 `joinedAt`  
- **仅标记**不影响佣金、不占 L/R、不触发滑落  
- **模拟购买入团**等价于现有 `addUser` 路径（扣 199、结算、可能滑落），允许指定 `joinedAt`

## §2 市场重排与结算

### 何时重排

每次**真实入团**（邀请购买 / 节点上「模拟购买入团」）结算插入子节点后，对挂靠父节点下的已入团真人直推调用 `sortMarketSiblings`。

复投 `(PS)` 点不参与左右位竞争，始终排在真人之后（扶持区）。

### 排序键

1. 有裂变优先：`realChildren(id).some(c => users[c].joined && !users[c].reentry)`  
2. 同档：`joinedAt` 新 → 旧  
3. 再同：稳定打破平局（如 id 字符串升序）

例：A 下 B1、B2、B3；仅 B3 有下级 → 顺序 **B3, B1, B2**。前两位为拼团区，第 3+ 为扶持区。

### 成团与滑落

- 人数算法不变：本人 + 名下复投 + **当前**前两名真人直推整棵已入团下级  
- `settleGroup`：`progress >= 7 && realDirectCount >= 2` 且尚未发过拼团奖  
- 允许先单链满 7，再补第 2 直推时补发拼团奖并 `applyReentries`  
- 滑落仍走重排后的 **左链最底**（`leftmostOpen`）

### 混合结算（模拟器语义）

| 动作 | 行为 |
|------|------|
| 新邀请 / 补单入团 | 按**当前**市场席位发本单奖金 |
| 已写入 orders / 钱包流水 | 日常路径不冲正 |
| 删除分支 / 整树重放 | 保留为演练能力（按保留订单重放）；与「日常不回改」在 README 中区分说明 |

## §3 UI 与操作

### 入口

选中节点后，侧栏（或点位详情区）增加「节点运营」：

| 控件 | 行为 |
|------|------|
| 代理等级 | 调用已有 `setAgentLevel` |
| 购买时间 | 已入团则改 `joinedAt` 并触发同级重排（不重发旧奖）；仅标记则改 `marketMarkedAt` |
| 仅标记已购 | `marketMarked=true`，树上角标「标记」 |
| 取消仅标记 | 清标记字段 |
| 模拟购买入团 | 未 `joined` 时按 199 入团结算，可用表单时间作 `joinedAt` |

复投 `(PS)` 节点：代理与购买编辑只读。

### 文案

- `README.md`、`index.html` 规则区：成团须直推 ≥ 2；团长仅直推 ≥ 3；席位按市场动态；历史奖金日常不回改  
- 去掉「席位不自动换位」等与新规则冲突的句子

## 与后端差异（刻意保留）

- 无真实订单 / CSRF / 数据库  
- 无「上级未入团 held 挂起」路径（模拟器邀请即入团）  
- 根节点「张三」等教学根可继续无购买；新增节点默认走购买入团，除非仅标记  

## 改动文件

- `assets/simulation-engine.js`：成团门槛、团长定义、`joinedAt`、市场重排、标记/入团 API  
- `assets/simulation-ui.js` + `index.html`：节点运营表单与树角标  
- `assets/styles.css`：标记角标等少量样式  
- `README.md`：规则同步  
- `tests/*.test.cjs`：单链不成团、第 2 直推补发、B3 挤到 L、团长仅直推 3  

## 验收用例

| 场景 | 期望 |
|------|------|
| 1 直推 + 长链满 7 | 进度可 ≥7，不成团、无拼团奖、无复投 |
| 上述后再招第 2 直推入团 | 补发拼团奖 + 滑落 |
| A 邀 B1/B2/B3，仅 B3 裂变 | 重排后 B3 为左位；七人计数吃 B3 树 |
| 节点设县/市/省代理 | 之后新单发对应代理奖 |
| 仅标记 | 树有角标，无 199 流水、不占 L/R |
| 模拟购买入团 + 自定义时间 | 入团结算；同档排序用该时间 |
| 直推满 3、七人未满 | 为团长；可影响订单奖向上截止 |
